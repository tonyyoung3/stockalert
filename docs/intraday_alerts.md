# 0050 盤中五分鐘急拉本機 App

盤中監控只在使用者的 Mac 執行，不部署到 Cloud Run、不使用 Cloud Scheduler，也不發 Slack。
App 開啟時每 60 秒檢查行情，符合規則時顯示 macOS 原生通知；關閉視窗就停止監控。

## 啟動

在 repository 的 Python 環境安裝相依套件後執行：

```bash
python -m notify.local_app
```

視窗提供「暫停」、「立即檢查」及「測試通知」。第一次按「測試通知」時，如果 macOS 詢問通知權限，請允許；
若沒有顯示，請到「系統設定 → 通知」檢查執行 Python／osascript 的應用程式權限。

可指定檢查間隔及狀態檔：

```bash
python -m notify.local_app --interval 30 --state ~/.stockalert/intraday.db
```

`--interval` 可設 30–60 秒，預設 60 秒。不要同時開啟兩個使用相同狀態檔的 App；本機檔案鎖會拒絕第二個程序。

沒有視窗的單次診斷仍可使用：

```bash
python -m notify.intraday_alert --once
```

## 偵測規則

只監控 `market.etf_members` 驗證通過的元大 0050 股票持股；不監控 ETF 本身或其他股票。
元大名單日期、版本會與每筆事件一併保存。每日 08:45–09:00（台灣時間）先同步名單；
若 App 開盤後才啟動，也會在抓行情前同步。

App 透過 yfinance 下載 `period=1d, interval=1m`、未還原分鐘資料，最多 4 個並行下載。
整批錯誤或全數沒有有效行情時退避 5 分鐘。

只使用已完成的正常盤一分鐘 K。最新完成分鐘的收盤價相對最近五根連續分鐘 K 的最低價上漲
**≥ 2%** 時觸發。例如 10:00–10:05 的最低價是 100，10:04 那根 K 在 10:05 完成且收盤 102，
就會通知。最低價只能精確到分鐘；不使用 high-low 振幅，因此先漲後跌不會只因振幅大而通知。

- 使用 09:00–13:30 成交資料，監控至 13:32，讓最後一根分鐘線抵達。
- 最新完成分鐘距檢查時間不得超過 120 秒。
- 缺分鐘、零成交量、NaN、無效價格、跨日或未完成分鐘不觸發。
- 啟動、資料中斷或重連後先暖機五分鐘；暖機期不補發舊訊號。
- 同一波只通知一次；條件先降到 2% 以下，而且距上次事件超過 15 分鐘，才能再次觸發。
- 使用 repository 的台股日曆；未知年度暫停。颱風等臨時休市沒有報價時不通知。

Yahoo／yfinance 不是有延遲保證的逐筆行情。分鐘內上漲後回落可能不會被偵測，延遲或缺漏也會略過。
視窗會顯示最後檢查時間、成分股數量、最大行情延遲及最近事件。

## 本機資料

預設狀態檔是 `.cache/intraday.db`：

- `intraday_state` 保存每檔股票的最後分鐘、重新啟用狀態及 15 分鐘冷卻時間。
- `intraday_events` 保存事件內容、通知時間或通知錯誤類型。
- 狀態保留 7 個日曆日，事件保留 30 個日曆日；下個交易日盤中首次檢查時清理。

事件與冷卻狀態在同一個 SQLite transaction 寫入，App 重啟不會重複通知同一根分鐘 K。
macOS 通知只嘗試一次；若通知權限被拒絕，錯誤會寫入事件並顯示在視窗，不補發過期通知。

App 必須保持開啟，Mac 也必須保持喚醒及連網。睡眠、關機或關閉視窗期間不會監控，也不會在恢復後補發舊訊號。
正式依賴前，至少在一個完整交易日觀察 `missing`、`stale`、`incomplete`、暖機狀態及實際行情延遲；
週末測試不能證明盤中通知的即時性。
